- Communicates in very terse, imperative prompts (e.g. "fix it") and expects the agent to diagnose the blocker and carry the fix through end-to-end rather than stopping at an explanation or a menu of options. Confidence: 0.78
- Wants to keep the specific library/tool they chose working (e.g. ragas) rather than having it swapped out for a custom reimplementation or alternative approach; pushes back ("i wanted to use rags bro i showed you error to fix") when the agent offers workarounds/options instead of fixing the reported error. Confidence: 0.7
- Uses a casual, informal register with the agent — addresses it directly (e.g. "bro") and asks blunt one-line questions like "why impro t not working" — rather than formal phrasing. Confidence: 0.55
- Reacts with frustration when told a fix is done or a behavior is explained away but the original problem still occurs; expects the agent to actually verify claims empirically — running the real code path (a fresh process, an actual query, repeated calls) — instead of reasoning about why the observed failure must be stale/cached or where the time "should" go. Confidence: 0.68
- Reports bugs by pasting the raw error text verbatim rather than describing the symptom in prose — cell output/tracebacks, IDE/linter diagnostics (e.g. Pylance "could not be resolved" with file context), and user-facing app error/warning strings (e.g. the app's own "The language model did not respond within 60s..." message) — and expects the agent to act on it rather than answer clarifying questions. Confidence: 0.8
- Prefers Pinecone over pgvector for storing RAG chunks/embeddings (explicitly requested swapping pgvector storage for Pinecone). Confidence: 0.6
- Prefers reversible, non-invasive fixes over ones that change system/OS-level settings: when Windows Smart App Control blocked scikit-learn, chose the in-code workaround rather than disabling Smart App Control (which can't be re-enabled without reinstalling Windows). Confidence: 0.65
- Favors architecturally clean solutions over fragile workarounds: chose adding a new clean ONNX-based (`fastembed`) embedding stack over monkeypatching a fake `sklearn` module to keep the existing `transformers` path. Confidence: 0.6
- Prefers Streamlit for building the project's interactive frontend/UI, wired on top of the existing pipeline (explicitly asked for a "full frontend" that uses the existing retrieval module for RAG question-and-answer), and expects it to work end-to-end — submitting a query and receiving the final generated answer, not just retrieved chunks/passages. Confidence: 0.7
- Wants chat answers to stream in incrementally (token-by-token) like ChatGPT-style UIs rather than appearing all at once after a loading spinner ("can we have answers in away like to show like stream"). Confidence: 0.6
- Strongly values speed and visible progress: repeatedly gets frustrated when the agent appears stuck "loading and doing nothing" or "taking minutes" without a result, and wants it to recognize a dead-end fast and abandon a wrong hypothesis (or bound/isolate a hanging step) rather than keep burning time; gets visibly angry ("bro what the fuck you r wating time", then again "why you are takingso much tim") when the agent keeps running extra verification/probe scripts after it already has enough to deliver the bottom line.
